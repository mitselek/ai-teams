## TLDR

An instrument's **match set** is the set of substrate states producing a given verdict. **When the match set is wider than the question, the instrument returns a clean-looking answer to a question it did not ask.** Rule: **establish that BOTH the PASS and the NULL are reachable on the substrate the check will run against**, before trusting it. Extends the standing one-sided rule (*"every probe carries what its null would mean"*): **a gate that cannot pass is worse than one that cannot fail informatively**, because it invites the opposite remedy.

## Key ideas

- **n=4, all observed by Hopper on 2026-09-02 (S71). AUTHORSHIP OF THE DEFECTIVE INSTRUMENTS: instances 1, 3 and 4 are BRUNEL's, instance 2 is Hopper's own** -- recorded per row at his request.
- **[THE MECHANISM, in Hopper's words] *"What would it look like if the executor did not have this? It would look exactly like the executor going quiet, which is indistinguishable from the executor working. That is a NULL WITH NO OBSERVABLE STATE."*** **Every instance has that property: the failed state and the working state produced identical observations from where the reader stood** -- which is why care and attention cannot catch it, there being nothing to notice. **It runs BOTH ways:** a check that **cannot report a real failure** (a gate that could never pass; an expected log string that is a shell VARIABLE NAME appearing in no version's output), and a check that **reports a failure that is not there** (a `tail` of an invented path, whose empty result reads as a dead service). The two invite opposite and equally wrong responses.
- **[1 -- UNREACHABLE NULL, Brunel's] `pgrep -af claude || echo NO_CLAUDE_PROCESS`** matches **its own wrapper** (the wrapper's command line contains `claude`), so pgrep always exits 0 and the null branch **can never fire**. Answered instead three independent ways: `pgrep -x` exits 1, `/proc/*/exe` scan empty, full `ps` empty.
- **[2 -- MERGED PATTERN REPORTS THE UNION, Hopper's own] one `grep -c` combining auth AND transport signatures returned `86`**, reading as "86 authentication failures" — enough to stop the rebuild. It is **0 auth**; the 86 are `rc=255` transport (`No route to host` 81 / `Network is unreachable` 3 / `Connection refused` 1 / `Connection closed` 1). Caught because **the sample lines printed beside the count contradicted what the count implied.**
- **[3 -- UNREACHABLE PASS, Brunel's] `docker run --rm <img> claude --version`** asked "does this ship 2.1.258?" and covered "does this image have an ENTRYPOINT that validates env first?" — **every** image in the family errors. **The CONTROL is the whole finding:** the same command against the known-good pre-build image returned the same error. Same verdict for good and bad inputs = no discrimination. Failure here invites *restore*, which **would have destroyed a correct build.**
- **[4 -- A DATA FIELD, NOT A COMMAND, Brunel's] `docker inspect ... Config.Image`** reads like "what is this container running" and answers "what string was typed when it was created". Carried here because it shows **the genus is not confined to instruments you invoke** — a field you read is an instrument, and its match set is equally unstated. Its own remedy is disjoint, so it is filed separately as [`live-is-not-the-same-as-discriminating`](live-is-not-the-same-as-discriminating.md).
- **THE CONTROL IS THE GENERAL FORM** (answers 1, 3 and 4): run the instrument against an input whose verdict you already know and **require the two verdicts to differ.** The corrected gate returned `2.1.258` vs `2.1.217` — two different strings, which the original could not produce for any input.
- **[INSTANCE 1 DEFEATED A RULE ITS AUTHOR HAD WRITTEN FOUR MINUTES EARLIER -- recorded as his own defect, at his request]** He had just committed that **every probe he sent would carry what its null would mean.** That probe **DID state its null meaning** (`|| echo NO_CLAUDE_PROCESS`, explicit) **and his own rule would have passed it clean.** **A rule that checks whether you STATED the null does not check whether the null can OCCUR** -- which is why the corrected form is two-part. Without this the entry reads as a discipline imposed on unnamed instruments; with it, a freshly-written rule failing on first use, caught by its author's own executor reading real output.
- **[REMEDY, ONE HABIT SPECIALISED FOUR WAYS] Process check: EXCLUDE THE CHECKER** (`pgrep -x`, `/proc/*/exe`, `grep -v grep`) -- self-matching by construction is the commonest instance. **Count: one pattern per class, report the DECOMPOSITION**, never the union under one label. **Gate: run it once against a KNOWN-GOOD subject as a positive control** before trusting any failure -- it needs no alertness, which is why it actually fires. **Data field: ask whether the value could have come out differently.** **Listing: `ls -la`, never `ls -l`**, when the subject may hold only dotfiles.
- **[WHY A HABIT AND NOT A LIST OF FIXES -- LOCATION MOBILITY] Brunel committed TWELVE instances of this genus in one session** -- six in commands he wrote, one in a gate, one in evidence he cited, one in message routing, three in the verification steps for a destructive operation. ***"Each time I hardened the location that had just burned me, and it moved."*** **Every one was caught by someone reading real output; none by him re-reading his reasoning** -- re-reading cannot surface a defect whose signature is the absence of one. **So fixing instances does not reduce the rate: the invariant travels and the locations do not**, and the remedy must attach to the ACT OF TRUSTING AN INSTRUMENT wherever it occurs.
